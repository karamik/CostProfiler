// Оптимизированная версия

func FastRouteOptimization(orders []Order) []Route {
// Preallocate slices
routes := make([]Route, 0, len(orders))
// Single pass O(n)
for _, order := range orders {
route := buildRoute(order)
routes = append(routes, route)
}
return routes
}

36.5 млн ₽/год
slow_route.go
// Исходная версия
// Cost: 843.2 млн ₽/год ⚠️
func SlowRouteOptimization(orders []Order) []Route {
var routes []Route // nil slice
// O(n²) — realloc на каждой итерации
for i := 0; i < len(orders); i++ {
for j := 0; j < len(orders); j++ {
route := buildRoute(orders[i], orders[j])
routes = append(routes, route) // realloc!
}
}
return routes
}
До оптимизации
843.2 млн ₽/год
Что изменилось?

Preallocate slices убрал O(n²) реаллокаций. Single pass вместо вложенных циклов. Результат: в 23 раза дешевле при том же объёме данных.

Ответы на возражения

Мы всё продумали

Решение

Мы фокусируемся на крупных логистических блоках и интерфейсах, которые Go не инлайнит. Для критических участков достаточно добавить //go:noinline — ничтожная цена за возможность экономить миллионы. 80% затрат лежит в 20% больших функций.

Решение

Динамический семплинг — мониторим каждый 100-й или 1000-й вызов. Оверхед <0.1% CPU, статистическая точность >95%. Как счётчик Гейгера: щёлкает не каждый распад, но общую картину видит идеально.

Решение

eBPF работает на уровне бинарника и ядра — язык не важен. Для 1С предоставляем адаптер через strace + парсинг RPC. 90% денег сжигают компилируемые языки — с них и начнём.

Решение

1) Единый статически скомпилированный бинарник — никаких зависимостей, только libc.
2) Предоставим SBOM и результаты пентеста для Security Review.
3) Пилот запускается на 2 небоевых контурах — вы сами видите результат без рисков.
